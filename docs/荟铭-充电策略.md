# 荟铭充电桩：收费标准与「充到 90% / 吃满时长」策略

> 数据来自 2026-10-23 抓包 + 2026-10-25 实盘（同一辆车、同一个站点）。
> 站点名、订单号、插座号已脱敏。

---

## 0. 一句话结论

**SOC 不用估 —— 电池日志里就有。**
这台车充的就是小哈那块电池：日志 `66.8V × 12.2A = 817W`，充电桩报 `826W`，差 1%。

策略三条，命中任一就结束：

1. **SOC ≥ 90%**（直接读 `battery.csv`）
2. **开始降压**：功率降到峰值的 90% 并持续 2 分钟
3. **购买时长剩 60 秒**：把买的时段用满，但绝不为最后几个百分点续费

## 1. 收费标准（实测）

计费 = 电费 + 服务费，两项都按**度**算：

| 项 | 价格 |
|---|---|
| 电费 | **0.69 元/度**（固定） |
| 服务费 | **按实时功率分 8 档** |

| 功率区间 | 服务费（元/度） | 综合单价（元/度） |
|---|---|---|
| 0–130W | 0.45 | 1.14 |
| 130–200W | 0.50 | 1.19 |
| 200–300W | 0.55 | 1.24 |
| 300–400W | 0.65 | 1.34 |
| 400–500W | 0.75 | 1.44 |
| 500–600W | 0.85 | 1.54 |
| 600–800W | 1.20 | 1.89 |
| **800–1000W** | **1.50** | **2.19** |

**你的车现在 826W，最高档，综合 2.19 元/度，其中服务费占 68%。**

`orders_money` 在充电中一直是 0.00，结束后才结算。

## 2. 「服务费吃满」到底指什么

你说的场景我理解为：

> 买了 2 小时，已经充到 1 小时 59 分，但还差几个百分点没满 —— 也停掉。

这就是**把买到的时段用满，但不为最后那一点续费**。

代码里的实现是 `--stop-before-end 60`：购买时长剩 60 秒就主动 `closeCharge`。
不是等桩自己停，也不是提前很多停 —— 是把 2 小时吃到 1:59，最后一分钟收尾。

**它和「充到 90%」是两个独立条件，谁先到算谁。**

| 场景 | 谁先触发 |
|---|---|
| 电池小 / 起始电量高 | SOC 90% 先到，1.5 小时就停 |
| 电池大 / 起始电量低 | 时长先到，1:59 停 |
| 电池进入恒压、功率掉下来 | 降压判据先到，比前两个都早 |

## 3. 为什么「开始降压就停」

锂电池充电分两段：

```
恒流段：功率稳定在峰值（826W），SOC 0 → ~80%，充得最快
恒压段：功率一路往下掉，SOC 80 → 100%，越充越慢
```

**降压段每度电的服务费最便宜（功率低 → 档位低），但耗时最长。**

以 2.7 度电池估算：

| 阶段 | 电量 | 平均功率 | 耗时 | 服务费 |
|---|---|---|---|---|
| 46% → 80% | 0.92 度 | 826W | 1.1 小时 | ≈1.38 元 |
| 80% → 90% | 0.27 度 | 300W | 0.9 小时 | ≈0.15 元 |
| 90% → 100% | 0.27 度 | 100W | 2.7 小时 | ≈0.12 元 |

最后 10% 只花一毛二，却要等将近 3 小时。降压就停，省的是时间。

> 至于降压是电池 BMS 的正常恒压，还是桩侧在限功率 —— 从外部数据分不出来。
> 但结论一样：**这一段不值得等**。

判据参数：

```bash
--droop-ratio 0.9    # 功率降到峰值的 90%（826 → 743W）
--droop-hold 2       # 持续 2 分钟才认，避免采样抖动误判
```

实测功率在 819~826W 之间小幅波动，不会误触发；真正进入恒压会一路掉到 700W 以下。

## 8. 三个反直觉的点

1. **功率越高，每度电越贵**：800W 档比 100W 档贵 1.9 倍。所以「高功率=划算」是错的。
2. **最后 10% 最便宜，但最慢**：服务费只要约 0.12 元，却要 2~3 小时。
3. **服务费没有起步价**：抓包里没有最低消费字段，「多充点摊薄服务费」不成立 —— 多充一度就多付一度。

真正贵的是 800W 档那 1.5 元/度，占综合单价的 68%，但这是车和充电器决定的，
除非换小功率充电器（更慢），否则控制不了。

## 9. 电流怎么设：档位内取最大，跨档位算时间

### 9.1 先纠正一件事：这家按「度」收，不按「小时」收

实测两单：

| 订单 | 电量 | 金额 | 折合 |
|---|---|---|---|
| A | 2.551 度 | 5.93 元 | **2.32 元/度** |
| B | 0.351 度 | 0.80 元 | **2.28 元/度** |

`type` 字段也写着「电量计费」。所以**同一档位内，充多久都不影响服务费总额** ——
服务费 = 电量 × 档位单价，只和充进去多少度有关。

> 你说的「不满一小时按一小时收」应该是别的平台（麦希充/铁塔那种按时长的）。
> 这里按度算，12A 充 1.5 小时和 14A 充 1.3 小时，只要充进同样度数，服务费一样。

### 9.2 但你的优化方向是对的：同档位内电流越大越划算

服务费按**功率**分档。只要功率还在 800–1000W 这一档：
- 12A 和 14A 的**服务费单价都是 1.50 元/度**
- 14A 功率更高 → 同样电量用时更短 → **不省钱，但省时间**

所以「已经吃到最高档，就把电流顶到该档上限」是成立的。

### 9.3 每档最大整数电流

按实测电压 66.9V（满电 67.2V）：

| 档位 | 服务费 | 该档最大电流 | 功率 | 每度成本 |
|---|---|---|---|---|
| 0–130W | 0.45 | 1A | 67W | 1.14 |
| 130–200W | 0.50 | 2A | 134W | 1.19 |
| 200–300W | 0.55 | 4A | 268W | 1.24 |
| 300–400W | 0.65 | 5A | 335W | 1.34 |
| 400–500W | 0.75 | 7A | 469W | 1.44 |
| 500–600W | 0.85 | 8A | 535W | 1.54 |
| **600–800W** | **1.20** | **11A** | **736W** | **1.89** |
| **800–1000W** | **1.50** | **14A** | **937W** | **2.19** |

按 72V 标称算则是：600–800W → **10A**，800–1000W → **13A**（14A = 1008W 超限）。

### 9.4 你的 13A vs 实际能到几 A

差别在**桩按哪个电压算功率**：

| 桩的算法 | 13A | 14A | 15A |
|---|---|---|---|
| 按实测 66.9V | 870W ✅ | 937W ✅ | 1004W ❌ |
| 按标称 72V | 936W ✅ | 1008W ❌ | 1080W ❌ |

**验证办法**：设 13A 跑一分钟，看桩报功率
- 显示约 870W → 按实测电压，可以升到 **14A**
- 显示约 936W → 按 72V 标称，**13A 就是上限**，别动

### 9.5 跨档位：最省不一定是最高档

以当前这单（还需 1.05 度、剩余 1.43 小时）为例：

| 电流 | 功率 | 服务费 | 每度成本 | 充满需时 | 来得及 |
|---|---|---|---|---|---|
| 11A | 736W | 1.20 | **1.89** | 1.43h | ✅ 卡点 |
| 12A | 803W | 1.50 | 2.19 | 1.31h | ✅ |
| 14A | 937W | 1.50 | 2.19 | 1.12h | ✅ |

**11A 每度便宜 0.30 元（约 14%），但只剩 0 分钟余量。**
所以：
- 想省钱且不怕卡点 → 11A
- 稳一点 → 12A
- 赶时间 → 14A

### 9.7 为什么 14A 会断开（实测答案）

不是功率超 1000W —— `14A × 66.9V = 937W`，离上限还有 63W。

**是电流本身的硬件上限。** 电池日志 2915 条里，电流最高只出现过：

```
13.25A   66.91V   887W   SOC 49%
```

从没超过 13.25A。所以限制来自 **BMS 或充电器**（最大充电电流 13A 档），
不是桩的功率保护。设 14A 时请求电流超过电池能吃下的值，触发过流保护 → 桩结束订单。

**结论：13A 就是最高档位内能用的最大值**（887W，仍在 800–1000W 档）。

### 9.8 悄悄踩到的坑：12A 正好卡在 800W 线上

电压是浮动的（64.5~66.9V），12A 的功率就在 **795~803W** 之间来回：

| 电压 | 12A 的功率 | 落哪档 | 服务费 |
|---|---|---|---|
| 66.5V | 798W | 600–800 | 1.20 |
| 66.9V | 803W | 800–1000 | 1.50 |

**同样 12A，可能按 1.20 收，也可能按 1.50 收。** 平台按实时功率分档，这种贴线的设置最不划算。

要么 **11A**（732W，离边界还有 68W，稳稳 1.20 档），
要么 **13A**（865W，稳稳 1.50 档）。
别停在 12A 这根线上。

## 10. 优化后的策略（2026-10-26）

### 10.1 分层，按优先级从上到下

| 顺序 | 条件 | 动作 | 理由 |
|---|---|---|---|
| 1 | SOC < `--soc-target`（90%） | 正常充 | 没到目标，不算账 |
| 2 | SOC ≥ 90%，**再充 1% > 3 分钟** | **立刻断** | 边际太差，等下去不值 |
| 3 | SOC ≥ 90%，**距整点 ≤ 1.5 分钟** | **整点前断** | 吃满当前计费小时，不跨档 |
| 4 | SOC ≥ 90%，边际还行且离整点远 | 继续充 | 还有性价比 |
| 5 | SOC = 100%（加了 `--hard-soc`） | 断 | 硬上限 |
| 6 | 功率有载 → 空载 10 分钟 | 断 | 拔车/桩停 |
| 7 | 购买时长剩 60 秒 | 断 | 不超时续费 |

> 「未接负载」那种由桩自己结束的情况，**本工具不做特殊处理**，只负责把结束事件推给你。

### 10.2 整点保护怎么算

**平台规则（牢大实测）：整点后有 2 分钟宽限** —— 1:00~1:02 之间停仍按 1 小时，
超过 1:02 才算第 2 小时。所以策略不是「整点前断」，而是**把宽限用满再断**。

```
1:00:00 ~ 1:01:00  继续（还能再等一轮）
1:01:30            断 → 按 1 小时结算
1:02:01 之后        已跨档，继续充到 2:00 前的宽限
```

- `--grace-min` 默认 **2 分钟**，`--pre-hour-min` 默认 **0**（不提前断，否则 59:00 就停，白丢 2.5 分钟）
- 断点选在 `grace − 轮询周期`，留一轮缓冲防网络延迟
- 跨档后不再干预，直接充到下一个整点的宽限
- 只有 SOC 过 90% 才启用

**如果平台其实按度计费**，这条只会让你少充一两分钟的电（约 0.02 度），不会多花钱。
`--no-hour-guard` 可以关掉。

### 10.3 到底会充到多少

不是固定值，取决于功率什么时候掉下来：

| 功率走势 | 结果 |
|---|---|
| 一直 870W 不掉 | 一路充到 100%（约 2 小时） |
| 95% 开始掉到 400W | 在 95~96% 断（4 分钟/% > 3） |
| 92% 就掉到 300W | 在 92% 断（5.4 分钟/%） |
| 90% 时快到整点 | 先吃到整点前，可能 91% 就断 |

**结论：90%~100% 之间，由功率和服务费档位实时决定。**

### 10.4 参数

| 参数 | 默认 | 作用 |
|---|---|---|
| `--soc-target` | 90 | 从多少开始算账（不是断电点） |
| `--value-max-min-per-pct` | 3 | 每 1% 超过 N 分钟就断 |
| `--pre-hour-min` | 1.5 | 距整点 N 分钟内断 |
| `--no-hour-guard` | 关 | 关闭整点保护 |
| `--hard-soc` | 关 | 到 100% 强制断 |
| `--capacity-kwh` | 0 | 电池容量（算每 1% 的量） |

### 11.2 账单核对：桩端计费 vs 电池端实充

```bash
python3 xiaoha/huiming_watch.py check
python3 xiaoha/huiming_watch.py check --order-id 11977507
```

```
订单    : 20261025200441282976
时段    : 10-25 20:04 → 20:41（37 分钟）
单价    : 电费 0.690 元/度，服务费 1.539 元/度
桩端 0.565 度 · 电费 0.39 + 服务费 0.87 = 1.26 元
电池端 82% → 100%，+8.10Ah ≈ 0.550 度
效率 97%
✅ 正常（90%±5%）
```

算法：`电池端度数 = (结束 Ah − 开始 Ah) × 平均电压 ÷ 1000`，再除以桩端 `electrics`。

| 订单 | 桩端 | 电池端 | 效率 |
|---|---|---|---|
| A | 0.565 | 0.550 | 97% |
| B | 0.997 | 0.940 | 94% |
| C | 0.485 | 0.451 | 93% |

**5 单全部在 93~97%，说明桩的计量是准的。**
低于 85% 才需要怀疑（桩多算、日志没覆盖全程、电池没均衡完）。

**watch 里已自动接入**：订单一结束就核一次，效率 <85% 会单独推一条告警。
